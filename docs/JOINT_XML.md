# Unattached joint XML

`load_joint_str` reads one current-schema `<joint>` into owned metadata.
`Joint::to_xml` emits its current name, kind, endpoints, raw pose/frame, axes,
axis dynamics/limits/mimic fields and modern screw pitch. It supports all nine
existing JointKind variants. Units stay in the stored representation: metres per
revolution for screw pitch, with linear/angular axis interpretation left to the
joint. Modern screw output preserves zero and signed zero without a reciprocal
legacy conversion. Source values and original XML provenance are not mutated.

This is unattached metadata. Unknown endpoint, pose, expressed-in and mimic-leader
references are retained without resolving a model graph. Local checks reject
identical endpoint spellings, child `world`, `__root__` endpoints, self-mimic of
the same axis slot and mimic slots other than `axis`/`axis2`. Full document loading
keeps its version gates, frame checks and resolved-body checks. Standalone
metadata admission does not make an invalid containing model valid.

The bounded API supports typed force_torque sensors in order; see
[FORCE_TORQUE_XML.md](FORCE_TORQUE_XML.md). Other sensor families, plugins and
opaque extensions, physics XML, an axis2 without axis, and a non-default pitch
on a non-screw joint return Unsupported. These values already
have owned storage in document-loaded joints; the writer reports the unsupported
payload instead of dropping it. Gearbox-specific XML fields remain unsupported
by the existing parser. Default Joint construction, mutable Element objects,
XML formatting preservation and general sensor serialization are outside this API.

Output uses quick-xml escaping and explicit `quat_xyzw` poses, retaining the raw
quaternion sign and relative-frame string rather than resolving world poses.
Transforms must be finite with unit quaternions under the existing validation
rule. Decimal subnormals rejected by the existing GNU reader are writer errors.
Endpoints must survive native text whitespace canonicalization. Attribute padding
and control characters that would change during parsing are rejected on output;
read-side native space/tab/newline trimming remains separate from graph lookup.
Axis output reuses the existing [axis contract](AXIS_XML.md), including its named
native normalization difference. No physics backend or performance claim follows
from this serialization capability.

## Evidence and remaining original assertions

`tests/joint_xml.json` records 23 actual native outcomes: eighteen accepted
metadata cases and five local rejections. All nine kinds, mixed Euler input,
modern screw pitch extremes and signed zero, both axis slots and unattached
mimic/frame references are represented. Typed comparisons use exact non-pose
values; seven raw pose components retain the original direct-sign absolute
`<=1e-3` Pose3 equality bound. Quaternion signs are not treated as interchangeable.

The checked-in native fixture is generated by the supported metadata subset of
DOMJoint.ToElement, without sensors. Its C++ generator and regeneration command,
pinned sources and linked libraries are in `reference/joint-xml.json`. The replay
checks byte-identical native generation, direct Rust loading of that fixture,
Rust read/write/read for the accepted corpus, and actual Rust XML loaded by native
Joint.Load. Low-level SDF parsing plus Joint.Load deliberately avoids Root/model
graph validation. The unchanged original native DOMJoint.ToElement also passes;
its type-none sensor errors on stderr are expected and retained in the result.

```
python3 tools/joint_xml_reference.py /path/to/pinned/sdformat
cargo test --locked --test joint_xml
```

The partial original port preserves supported raw pose/frame, name/endpoints,
Ball kind, both axis presence/direction and edited-parent roundtrip assertions.
XML setup replaces default C++ DOM construction. Constructor Element identity,
AddSensor/duplicate/ClearSensors, source sensor lookup and source Element presence
contracts remain unported by this selected case. The original sensor count
assertion compares the source count to itself; this port makes no loaded sensor
count claim. Existing sensor API tests are separate. The original stays partial,
and its unsupported assertions remain in the ledger.

The initial joint XML slice passed independent source/assertion/error-boundary
review, a fresh 48-test Rust replay, all 23 native outcomes and both exchange
directions, followed by strict staged coverage and exact hosted CI. Its reader
diagnostics preserve the caller URI and root location. That slice added one
partial mapping, bringing accepted counts to 169 complete and 30 partial by
reviewed status across both lists. The force/torque extension's current evidence
and remaining gates are recorded in [FORCE_TORQUE_XML.md](FORCE_TORQUE_XML.md).

## Invalid default-sensor case in the native original

The unchanged DOMJoint.ToElement original inserts three default sensors of type
NONE, checks unique insertion/duplicate refusal/clear and checks the source
objects by index. Native Joint.ToElement reuses GetElement("sensor") for each
copy, so the emitted XML retains only sensor2. It logs unsupported-NONE conversion
messages. Loading that XML returns error code 5 but retains the joint fields and
one NONE sensor. The original ignores that Load result and compares the source
SensorCount to itself, not to the loaded count. Its edited-parent load also
returns code 5. The constructed Joint keeps a null input Element after output;
the loaded object's Element records the supplied input.

These observations do not justify a success-returning Rust loader for invalid
sensor data or reproducing the native producer's sensor loss. The strict writer
and document admission remain unchanged; supported force/torque envelopes keep
their full order. This exact original remains partial, including its constructor
origin and NONE-sensor behavior. No insertion-helper or partial-diagnostics API
was added merely to imitate the invalid-data case. The source basis is pinned
Joint_TEST.cc:266–331, Joint.cc:581–587 and Sensor.cc's NONE admission/output paths.
