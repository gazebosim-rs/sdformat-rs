# Lidar XML

`Lidar::to_xml` and `load_lidar_str` preserve horizontal/vertical samples,
resolutions and raw angles, range metadata, visibility mask and Noise kind/mean/
standard deviation. The standalone reader reuses existing node parsing, required
scan/horizontal/range checks, defaults, numeric policy and caller locations.
Output uses current typed values without mutating input provenance.

Metadata admission does not generate rays or impose runtime ordering. The retained
original has vertical min 0.54 > max 0.321 and range resolution 5.6 larger than
its span; these values are preserved. Negative/zero scan resolution, inverted
ranges and large raw angles also roundtrip when admitted by the existing reader.
Runtime consumers validate any values they actually use to allocate or trace rays.

The native Lidar grammar writes only Noise type/mean/stddev. Nondefault retained
bias mean/deviation, dynamic bias deviation/correlation and precision return
Unsupported. Each omitted field must have exact +0 bits: -0 also rejects instead
of losing its sign. Emitted mean/stddev and scan/range fields retain signed zeros.
Emitted floating fields must be finite and non-subnormal; existing negative Noise
stddev rejection remains. No additional physical bounds are introduced.

Matching standalone Sensor output supports canonical lidar and gpu_lidar, retaining
current envelope/pose metadata. Existing legacy ray/gpu_ray parsing and public kind
strings remain unchanged; output for those declared kinds and legacy standalone
roots rejects. A canonical GPU Sensor with a ray payload is covered by actual
exchange. Joint XML remains force_torque-only. Plugins, extensions, gz_frame_id
and mismatched families still reject; this is not general Sensor or runtime parity.

## Native and original evidence

Thirty-four actual native cases cover effective defaults, independently varying
scans/ranges, inverted and negative metadata, signed zeros, finite extremes, all
Noise kinds and five Sensor envelopes. Numeric controls preserve existing Linux
stoul prefix/bool/u32-wrap behavior for sample counts and masks; ulong overflow
and malformed float inputs reject. Thirty-one actual Rust outputs load in native
Lidar/Sensor. Non-pose projections compare exact bits; pose components retain
direct signs and <=1e-3 bounds. The native original fixture is regenerated byte
for byte. Source/library identities are in reference/lidar-xml.json.

```
python3 tools/lidar_xml_reference.py /path/to/pinned/sdformat

```
